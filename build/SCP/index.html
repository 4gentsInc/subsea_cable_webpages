    Subsea Cable decision log¶

    This log records every accepted Subsea Cable Proposal (SCP) as its final accepted result. It is append-only: each activation adds one entry at the end, and existing entries are never edited, reordered, or removed.

    An entry states only the decision that took effect: its number and title, status, effective language revision, the accepted rule and its scope, and the earlier decisions it supersedes. It omits the process that produced the decision. Proposals under discussion are not listed; a proposal appears here only after its activation makes it Accepted.

    A later decision never rewrites an earlier entry. Supersession and correction are recorded by a new entry that names what it replaces, so the current rule for a topic is found by reading from the end. Within its stated scope, a later entry replaces every conflicting earlier rule.

    The log records which decisions took effect. The canonical rules themselves are maintained in the Language Reference, the ANTLR and EBNF grammars, the Runtime Contract, and the conformance corpus. When an entry and a canonical source appear to disagree, report the conflict; do not choose one silently.

    Numbers 0012 and 0013 were allocated but never accepted. They remain unused.

    SCP-0001 — Touchdown consumption and window counting¶

    • Status: Accepted
    • Effective language revision: eabb5052b674901e107aed385cbf5d61a122d618
    • Supersedes: —

    Decision:

    • A published Touchdown leaves the Touchdown window through exactly one applied acknowledgement: a consume acknowledgement at the first dispatch of its evaluation instance, applied before the Host is invoked, or a discard acknowledgement when it will never be attempted.
    • The window counts every published grounded leaf without an applied acknowledgement.
    • Window backpressure limits only speculative prefetch. Explicit Scheduler demand is always deduced.

    SCP-0002 — Carousel, Vessel, and Runtime value ownership¶

    • Status: Accepted
    • Effective language revision: 79debc4fe1106ccdee96278811b74609468e7dd6
    • Supersedes: the use of Vessel as the name of the deduction component

    Decision:

    • The Carousel is the demand-driven deduction engine. Vessel names the complete Consumer Runtime; it is not a second deduction component.
    • The still-unexposed region is the Folded Cable. The undeduced frontier contains occurrences that already exist but have not committed a deduction.
    • The Runtime owns the Outcome & Value Store. The Scheduler delivers evaluation outcomes to it, and the Carousel reads resolved routed values through a narrow read-only port.
    • The Codebase stores artifacts, aliases, revisions, and deduction records, never live evaluation outcomes or routed runtime values.

    SCP-0003 — Explicit staging of value-producing calls¶

    • Status: Accepted
    • Effective language revision: 79debc4fe1106ccdee96278811b74609468e7dd6
    • Supersedes: argument-position staging of value-producing calls

    Decision:

    • Outside an arrow-function leaf body, an eager Goal call Goal(...) or Anchor call $anchor(...) must occupy a direct structural occurrence position. It may not be nested inside another Goal or Anchor argument, a policy argument, a lookup key, an operator operand, or an ordinary value container. A hidden evaluation dependency is InvalidStructuralContext.
    • Primitive expressions such as B[x + 1] remain valid deduction-time value expressions because they create no occurrence, Scheduler work, or effect.
    • Inside an arrow-function leaf body, nested $anchor(...) calls remain valid and are evaluated by the Host as part of that one leaf. Subsea Goal calls remain forbidden there.

    SCP-0004 — Voyage Plans and Fully Touchdown Cable artifacts¶

    • Status: Accepted
    • Effective language revision: 003b1e2404e01ad3e33eee8781ec2f408055091c
    • Supersedes: the source-level equation "Program = Cable" and the .subc source extension

    Decision:

    • A Subsea Cable source file is a Voyage Plan with the .vyg extension. A Vessel accepts the plan and carries the Frontend, Codebase, Carousel, Outcome & Value Store, Scheduler, and Host ports needed to realize it. The Carousel remains the only deduction engine.
    • A terminated voyage produces a Fully Touchdown Cable, a canonical ordered list of grounded-leaf content hashes, and the Root outcome.
    • Cable order compares each leaf's root-to-leaf vector of child ordinals lexicographically, with ordinals assigned from authored result order. Deduction, completion, and dispatch timing never reorder the list, and structural sharing never collapses distinct evaluation instances.
    • A Touchdown hash identifies grounded structural content only. Run and occurrence identifiers, list positions, lineages, timestamps, attempts, outcomes, and ordered policies are excluded. Equal hashes do not prove equal Host effects or results.
    • Provenance, lineages, dependency observations, and reverse lookup live in a sidecar index that supports both deduction-to-cable-range and cable-position-to-deduction-ancestry lookup.
    • A later voyage may reuse an earlier immutable segment only when the policy-erased structural identity, canonical arguments, applicable profiles, alias observations at stable reference slots, and required value observations all match. Reuse commits new records that refer to the earlier segment with reusedFrom; it never edits an earlier record. Structural reuse never implies reuse of a Host outcome or effect.

    SCP-0005 — Guarded conditional recursion¶

    • Status: Accepted
    • Effective language revision: 6110c1713ec246848ab4421894ae27835f30c580
    • Supersedes: the rule that every recursive Goal-definition cycle is CycleDetected

    Decision:

    • A pure selector expression followed by a keyed conditional branch map forms one structural pipeline, for example [n == 0, {true: Done[], false: CountDown[n - 1]}].
    • The selector is evaluated through Host primitive semantics, and exactly the selected branch is exposed. Unselected branches create no occurrences and perform no alias or value observations. A selected recursive branch creates a fresh child occurrence, never a back-edge to an earlier occurrence.
    • A recursive definition component is valid when every definition-level cycle is guarded by such a conditional selection and the guarding map has at least one branch that exits the component. An unconditional cycle, or a conditional cycle with no exit branch, remains CycleDetected.
    • Crossing any selected conditional branch edge is an explicit-demand boundary. Speculative replenishment never demands or deduces the selected child.

    SCP-0006 — Live Vessel–Host cooperation¶

    • Status: Accepted
    • Effective language revision: 6110c1713ec246848ab4421894ae27835f30c580
    • Supersedes: any interpretation of Vessel as a compiler that hands a completed Cable to a detached Host

    Decision:

    • A general-purpose Vessel remains a logical participant throughout a voyage. Deduction reaches grounded leaves, the Scheduler offers eligible evaluation instances to the Host, Host outcomes and values return, and those values may unblock or select later deduction until the voyage terminates.
    • This is a semantic lifecycle requirement, not a deployment requirement. The participants may communicate across processes or run in one process.
    • Validation, normalization, artifact caching, and binding generation are not deduction. They leave every unqualified Goal occurrence symbolic until that exact occurrence is demanded in a voyage. A producer that emits code or a prospective leaf manifest and then relinquishes the voyage is not by itself a conforming Runtime; generated code conforms when it embeds or links the same live feedback loop.

    SCP-0007 — Occurrence kind for inline Goal-arrow stages¶

    • Status: Accepted
    • Effective language revision: 6110c1713ec246848ab4421894ae27835f30c580
    • Supersedes: —

    Decision:

    • An inline Goal-arrow stage such as [{code, logs}] -> Diagnose[code, logs] is an occurrence of kind goal-arrow-stage.
    • It stays undeduced until it is demanded and its routed input resolves. Its deduction binds the input to its parameters (a mismatch is a deduction-phase DestructureMismatch), reduces its body, and commits a record with referenceKind = inline-arrow, the parameter arity, no requested name, and no artifact hash.
    • It adds no lineage segment, and its children inherit the enclosing Goal lineage. It does take one child-ordinal segment in every descendant leaf's ordering vector.
    • A Scheduler-addressed policy may target it. As a composite, Reattempt on it is UnsupportedPolicyTarget. A Host-addressed policy may not target it.

    SCP-0008 — Top-level values in artifact identity¶

    • Status: Accepted
    • Effective language revision: 6110c1713ec246848ab4421894ae27835f30c580
    • Supersedes: —

    Decision:

    • A stored Goal artifact captures, in canonical order, the transitive closure of top-level value bindings its term references by name.
    • Captured values are part of both the authored and the structural projection; policies inside them are erased only in the structural projection.
    • Goal references are not captured. An unqualified reference stays symbolic and resolves when its own occurrence is demanded.
    • A structure-valued lookup map is captured by structure: its keys and entry shapes enter the capturing artifact's hash, unqualified Goal references in its entries stay symbolic, and hash-qualified references keep their pinned hash.
    • Captured values are authored identity. They are unrelated to the runtime value observations recorded for reuse.

    SCP-0009 — Structure-valued ordinary lookup maps¶

    • Status: Accepted
    • Effective language revision: 6110c1713ec246848ab4421894ae27835f30c580
    • Supersedes: —

    Decision:

    • A structure-valued lookup map is a top-level non-Goal binding whose right-hand side is a map literal whose entry values are Goal structure.
    • Each entry must be written with an explicit suffix: a deferred Goal reference A[], an Anchor reference $a, or a serial or parallel composition of those. A bare identifier entry, an inline Goal-arrow entry, or use of the map as a value is InvalidStructuralContext.
    • A brace literal inside an entry is an ordinary map, not a resolving map.
    • The map may be used only in a Goal-structure position, selected by lookup such as Routes[key]. The selected entry receives no implicit upstream value; routing must be explicit in the entry.
    • A named structure-valued map is not a conditional branch map: [sel, Routes] is a two-stage serial composition.

    SCP-0010 — Errors for NoOutput where a value is required at runtime¶

    • Status: Accepted
    • Effective language revision: 6110c1713ec246848ab4421894ae27835f30c580
    • Supersedes: —

    Decision:

    • A Host leaf that returns NoOutput where a value is required produces the single error kind NoOutputNotRoutable.
    • Its phase is deduction when detected while routing into a deduction (a routed input or a resolving-map result being bound), and host when detected inside a function-leaf body.
    • The error is scoped to the failing occurrence. Earlier committed deductions are unaffected, and recovery remains Scheduler policy.

    SCP-0011 — Policy addressee and the Host policy channel¶

    • Status: Accepted
    • Effective language revision: 6110c1713ec246848ab4421894ae27835f30c580
    • Supersedes: the assumption that every @policy is addressed to the Scheduler

    Decision:

    • A policy that changes eligibility, the attempt lifecycle, or a scope's outcome is Scheduler-addressed. A policy that changes only what happens inside exactly one grounded leaf invocation is Host-addressed. Batching or coalescing several leaves is Scheduler-addressed.
    • A Host declares the policy identifiers it accepts in its capability description. An identifier claimed by both the Scheduler registry and the Host is PolicyConflict; one claimed by neither is UnknownPolicy. Both are policy-phase errors.
    • The Scheduler registry, the Host capability, and the forwarding allowlist are pinned at run start, and every occurrence's policies resolve against those pinned identities.
    • A Host-addressed policy may target only a grounded function leaf or Anchor. A composite's policy is never forwarded to its descendant leaves.
    • The Host-facing evaluation request carries only hostPolicies[], the source-order Host-addressed subsequence of directPolicies[], and never directPolicies[] itself. A Host-addressed policy has no authority over the attempt lifecycle, and cancellation stays cooperative.

    SCP-0014 — Laid Cable channel semantics and Goal output multiplicity¶

    • Status: Accepted
    • Effective language revision: e4dfaf2271cfb98b05c34783bd461303c9dcc4fa
    • Supersedes, in part:
    • SCP-0003: the input-bearing Root and Anchor-bodied Goal in its example; the staging rules are unchanged.
    • SCP-0004: one Root outcome per voyage, and untagged child-ordinal ordering.
    • SCP-0006: the lifecycle from Root demand to one Root outcome.
    • SCP-0010: NoOutputNotRoutable for absence on a routed Goal-to-Goal or Cable edge.
    • SCP-0011: pinning once at run start.
    • The input-bearing Root form, the single-result Goal assumption, the NoOutput-exporting unkeyed parallel rule, and the resolving-map "exports a value" rule.

    Decision:

    • A Goal is not a synchronous function. An authorized outward caller lays a Goal target as a live Cable with lay(goalRef), sends each input with send(cable, tuple), and ends admission with decommision(cable). There is no input-bearing one-shot evaluation. A Voyage Plan names its default target with root Name/inputArity.
    • Every authored Goal connection behaves as an implicit FIFO channel-equivalent edge. Unconsumed right-end Values are observed by the outward caller.
    • Each admitted input is one result segment ending in exactly one EndOfResult(outcome), which carries no identifier. Only one segment is active; the next input begins only after the active segment's terminal has propagated. A failed or cancelled segment terminates only that segment and keeps what it already published.
    • EndOfStream is produced only after decommision and complete drainage. It aggregates no outcome. The final result is the Fully Touchdown Cable plus one ordered outcome per admitted Input(k).
    • A Goal signature is Name/inputArity/outputMultiplicity, with multiplicity exactly 0, 1, or N. Plain -> asks the frontend to infer it; -0>, -1>, and -N> declare it on a named Goal when it cannot be inferred without observing a mutable alias or runtime state. Function leaves are always /1. Multiplicity is part of structural identity but never an alias or overload key.
    • A routed downstream Goal runs once per upstream Value. /0 and an empty /N invoke it zero times and are not errors. A missing /1 Value is OutputMultiplicityMismatch. A Goal never picks a first Value, collects Values implicitly, or is partially applied.
    • Cable order is Input(k) followed by tagged positions: Authored(k) from authored reduction order and Emission(k) from the zero-based FIFO position of a /N Value. Positions are provenance, never part of a Touchdown hash.
    • The Scheduler registry, Host capability, and forwarding allowlist are pinned when each input is admitted. A pin failure rejects that send with ProfileNegotiationFailed.
    • Not part of this decision: result-scope objects, channel-of-channels models, yield, lazy-list or stream values, partial application, Anchors receiving a Cable, concurrent processing of separate inputs, and cross-input merge operators.

    SCP-0015 — Vessel control plane, Cable data plane, and Agent-authored replanning¶

    • Status: Accepted
    • Effective language revision: 73d58594dd4152c1bcfd806a88b9ba845213d66f
    • Supersedes, in part:
    • SCP-0001: the Carousel as owner of speculative replenishment and receiver of consumption acknowledgements. The consumption point, counting rule, explicit-demand exemption, and overshoot diagnostics are unchanged.
    • SCP-0002: Vessel as the whole-Runtime name, Carousel ownership beyond one atomic deduction, and undifferentiated Runtime ownership of the Outcome & Value Store.
    • SCP-0004: Vessel as the complete Runtime and outward product boundary, and ownership of final result assembly.
    • SCP-0006: one undifferentiated Vessel owning the whole live loop. The compiler-only prohibition and deployment neutrality are unchanged.
    • SCP-0011: policy interpretation described as occurring inside a whole-Runtime Vessel. The addressee rules are unchanged.
    • SCP-0014: Vessel ownership of laid-Cable channel execution and data-plane termination.

    Decision:

    • The Subsea Cable Runtime is the deployment-neutral whole. It contains the Vessel control plane, the Cable data plane, the Codebase and append-only deduction ledger, the Scheduler and Host ports, and a stateless outward composition layer.
    • The Vessel control plane owns the voyage, the occurrence set, the undeduced frontier, coordination of explicit and speculative structural demand, Touchdown-window accounting, publication of committed structure, and the determination that no structural work remains. It carries no channel frames and owns no Outcome & Value Store.
    • Carousel performs one atomic deduction requested by Vessel: it resolves the occurrence's current alias when applicable, applies its reduction rule with supplied arguments and values, and commits one complete deduction record or none. It does not choose demand, own the frontier, or evaluate leaves.
    • The Cable data plane owns installed topology, input admission and declaration leases, channels and backpressure, routed Values, the Outcome & Value Store, Host emission sessions, multiplicity enforcement, drainage, and terminal propagation. It never reads a mutable alias or creates a deduction record. The Scheduler keeps outcome authority, and the Host keeps primitive, leaf, Anchor, and Host-addressed policy semantics.
    • Vessel publishes each committed result to Cable as one idempotently identified TopologyInstall. Cable exposes none of it as executable until it acknowledges TopologyInstalled; a stale, malformed, or identity-conflicting installation is TopologyInstallRejected and publishes nothing. Until acknowledgement, each newly grounded leaf occupies one pending-install window reservation.
    • A segment's EndOfResult requires both Vessel structural closure and Cable drainage of all installed caused work. EndOfStream additionally requires decommission, closed structural publication, every segment terminal, and full drainage.
    • The final result is assembled by the stateless composition layer from immutable Vessel provenance and Cable completion evidence. Outward adapters attach to that layer, never to plane-private storage.
    • An Agent or operator, never Vessel, authors replanning. After observing authorized Cable output, it may store a new immutable artifact and atomically rebind Name/Arity. Only later-demanded undeduced occurrences observe the new binding; committed deductions and installed topology never change.
    • Process placement never changes alias-observation time, deduction identity, Value order, or terminal semantics.
