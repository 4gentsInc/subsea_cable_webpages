    Laid-Cable Conformance Scenarios¶

    These scenarios specify observable Subsea Cable Runtime behavior across the Vessel control plane and Cable data plane for laid Cables, per-input result segments, terminals, and Goal output multiplicity defined by SCP-0014. Plane ownership and the completion handshake additionally follow SCP-0015. A single source fixture cannot express them. They need a live Cable, deterministic Host doubles, and a controllable Scheduler, and they are normative for an implementation claiming laid-Cable conformance.

    Every scenario uses the outward operations lay(goalRef), send(cable, input), and decommision(cable). They are Runtime operations, not Voyage syntax, and lay always takes a named Name/inputArity reference: composite structure is laid through a named wrapper Goal, never as an anonymous arrow. Unless a scenario says otherwise, the Codebase holds this unit:

    P = [x] -N> $p(x)
Q = [x] -1> $q(x)
Z = [x] -0> $z(x)
S = [v] -0> $sink(v)

PThenQ = [x] -> [P[x], Q]
PThenS = [x] -> [P[x], S]
QThenS = [x] -> [Q[x], S]
ZThenQ = [x] -> [Z[x], Q]
Fan    = [x] -> {Q[x], P[x]}

root PThenQ/1

    $p, $q, $z, and $sink are deterministic, recording Host doubles whose emissions, terminals, delays, and failures each scenario programs. The bracketed identifiers after each heading are stable coverage identifiers: plain numbers cover the laid-Cable decisions of SCP-0014, and R numbers cover the Runtime-plane decisions of SCP-0015. Identifiers satisfied by source fixtures are mapped in the final section.

    1. Host result multiplicity [1, 2, 3, 4, 60]¶

    Lay Z/1, Q/1, and P/1 and send one input to each.

    • Z succeeds with no Value: the right end observes only EndOfResult(Succeeded).
    • Q emits one Value: the right end observes that Value and then EndOfResult(Succeeded).
    • P emits zero, one, and three Values in three separate segments; each is followed by exactly one EndOfResult(Succeeded).

    Then lay QThenS/1 and ZThenQ/1 so each violation has downstream work:

    • $q emits one Value and then a second. The second MUST be rejected before routing. S MUST run exactly once, for the first Value, and that run and its effects are not rolled back. Only after that S run terminates does the segment emit exactly one EndOfResult(Failed(OutputMultiplicityMismatch( expected = /1, context = host-emission))).
    • $q completes successfully with zero Values: S runs zero times and the segment emits exactly one failed EndOfResult with the same diagnostic.
    • $z emits a Value: it MUST be rejected before routing, Q runs zero times, and the segment emits exactly one EndOfResult(Failed(OutputMultiplicityMismatch( expected = /0, context = host-emission))).

    2. /N Host terminals [5, 61, 62]¶

    Lay PThenS/1 and program $p:

    1. Emit two Values, a successful Host terminal, then a third Value.
    2. Emit one Value and two successful terminals.
    3. As variant 1, but make the second S run fail.
    4. Emit one Value and return normally with no terminal.

    The first terminal seals the emission session. In variants 1–3 the late Value MUST be rejected before routing and recorded as HostTerminalProtocolViolation(kind = late-value), and the second terminal MUST be recorded as kind = duplicate-terminal. Neither changes the successful Host emission result nor creates a second EndOfResult. S runs once per accepted Value, and the segment's single outward EndOfResult follows only after those runs drain: Succeeded in variants 1 and 2, Failed in variant 3, showing that the Host terminal did not fix the segment outcome. In variant 4 S MUST run once for the accepted Value and finish, and then the segment emits exactly one EndOfResult(Failed(HostTerminalProtocolViolation(kind = missing-terminal))).

    3. Silence is not termination [6]¶

    Lay P/1, send an input, and let the Host double stay connected without emitting. The segment MUST remain pending indefinitely; no EndOfResult, NoOutput, or success is inferred. With @timeout authored on the leaf, the Scheduler policy ends it with the corresponding non-success outcome.

    4. One active input segment [7, 15, 33, 35]¶

    Lay PThenQ/1 and send two inputs before the first segment ends.

    • No occurrence of the second segment is disclosed, deduced, prefetched, alias-resolved, or dispatched until the first segment's EndOfResult has propagated and its caused work has drained.
    • No Value, attempt outcome, or routed binding from one segment satisfies an occurrence, value barrier, or binding in the other.
    • Cable-level state (queue, buffers, lifecycle) is inspectably separate from each segment's Outcome & Value Store and deduction namespace.

    5. Immediate intra-segment flow and per-Value routing [8, 39, 40, 41, 45]¶

    Lay PThenQ/1 where $p emits 10, 20, 30 with a controllable delay between them. Q MUST be invoked for 10 before P emits 20. Exactly three complete Q/1 evaluations occur in FIFO order and the composite is /N. When P emits nothing, Q is invoked zero times and the segment succeeds. No first-Value selection, collection, or multiplicity failure occurs.

    6. Authored sinks [9]¶

    Store this unit and lay PrintPrimes/1:

    PrintPrimes = [limit] -> [Eratosthenes[limit], PrintPrime]
PrintPrime  = [prime] -0> $PrintLn(prime)
Eratosthenes = [limit] -N> $eratosthenes(limit)
root PrintPrimes/1

    Send 20. One PrintPrime/1 and one $PrintLn invocation MUST occur per prime, each visible as its own occurrence with its own outcome. The segment's EndOfResult MUST wait until all of them terminate. No cable Voyage variable exists and no terminal frame is passed as an Anchor argument.

    7. Decommission and EndOfStream [10, 50, 63]¶

    Lay the plan's default target PThenQ/1, send three inputs, make the second fail, then call decommision.

    • A later send MUST return AdmissionClosed and consume no Input(k).
    • All three accepted segments drain, including the one after the failure.
    • EndOfStream is emitted once, after the final EndOfResult, and carries no aggregate outcome.
    • Race a send against decommision many times. Exactly the sends whose admission commit wins receive contiguous ordinals; each loser releases any pins it acquired and returns AdmissionClosed. A send blocked in a slow pin attempt before admission MUST NOT delay EndOfStream.

    8. Full tuple binding and routing shorthand [11, 16, 46]¶

    • [A, B] with a unary B routes each A Value into B; no other arity has a bare shorthand.
    • [A, B[y]]: A is still demanded and evaluated, its effects, Touchdowns, outcome, and provenance remain observable, and only its routed Values are discarded. B is invoked once with its written tuple, and the composite takes B's multiplicity even when A is /N.
    • No written argument list is ever completed from an upstream Value.

    9. Multiplicity and identity [12]¶

    Store F = [x] -1> $f(x) and a variant F = [x] -N> $f(x) in successive codebase revisions. Their StructureHash values, and therefore GoalNodeId, MUST differ. Publishing both under F/1 in one revision MUST be rejected: an alias key is Name/inputArity only, and multiplicity is never an overload axis. A memo key containing GoalNodeId distinguishes the two.

    10. Emission positions [13, 14]¶

    Let P emit three equal payloads. Their downstream occurrences MUST carry Emission(0), Emission(1), Emission(2) position segments. The payloads are unchanged and carry no ordinal. Repeat with the Host completing downstream work in reverse order; the Fully Touchdown Cable order MUST be identical, following tagged Authored(k) and Emission(k) positions (Authored before Emission at a common parent) rather than completion timing.

    11. Adapter surface [19]¶

    Every TUI, MCP, library, and service adapter MUST expose arbitrary-Goal debugging only as lay(goalRef) plus separate send and decommission operations. None may expose evaluate(goal, arguments) or an equivalent that combines lay, send, and an implicit decommision.

    12. Parallel composite terminal [20, 43]¶

    Lay Fan/1. The right end MUST observe no Value and exactly one EndOfResult carrying the Scheduler-determined scope outcome. Branch terminals remain internal regardless of their arrival order.

    13. Channel capacity [21, 22, 23]¶

    Run scenario 5 with capacity 0, 1, and the profile default. Values, terminals, outcomes, and the Fully Touchdown Cable MUST be identical; only blocking may differ. A Host send that blocks on a full channel remains one active attempt, never reclassified as undispatched. Touchdown prefetch and channel capacity each enforce their own bound: shrinking one does not relax the other.

    14. Admission pins [24, 25, 26, 27, 28, 29]¶

    • lay alone creates no segment and pins nothing.
    • Each accepted send pins the Scheduler registry, Host capability profile, and forwarding allowlist before any disclosure or deduction for its segment.
    • A send whose pin fails returns ProfileNegotiationFailed and produces no segment, occurrence, Cable member, or EndOfResult.
    • Change a declaration between two sends: the segments record different immutable pin sets.
    • A queued admitted segment keeps its snapshots resolvable until its terminal propagates, with no repinning when it activates. An attempt to evict a pinned snapshot is reported as a Runtime contract violation. A Host endpoint outage under a retained pin is an ordinary attempt failure.

    15. Demand-time alias per segment [30, 31, 32, 34]¶

    Lay unqualified Root/1, send an input, rebind Root/1, then send another. The later segment MUST select the artifact visible when its own Root occurrence is demanded. A queued segment observes no alias before it becomes active. Rebinding never changes an already deduced occurrence. A shared ledger backend keeps each segment's deduction namespace distinct.

    16. Input provenance and the final result [36, 37, 38, 47, 48, 49]¶

    Lay PThenQ/1 and send four inputs where the second is rejected (arity) and the third fails.

    • The admitted inputs receive Input(0), Input(1), Input(2); the rejected send has no ordinal.
    • The same inner occurrence path in two segments stays distinct through its Input(k) prefix.
    • The Fully Touchdown Cable concatenates segment lists in increasing Input(k) order. The ordinal appears in no control frame and no Touchdown content hash.
    • The failed segment keeps its published Values, effects, deduction records, and Touchdowns, and the following segment starts normally after the failed terminal propagates and drains.
    • The final result contains one SegmentOutcome(Input(k), outcome) per admitted input, in ordinal order.

    17. Empty routed segments [17, 18]¶

    Lay ZThenQ/1, and lay PThenQ/1 with $p emitting no Value before its terminal: in both, Q MUST be invoked zero times and the segment ends EndOfResult(Succeeded) with no NoOutputNotRoutable. Lay QThenS/1 with $q succeeding with no Value: S runs zero times and the segment MUST fail with OutputMultiplicityMismatch(context = host-emission), not NoOutputNotRoutable.

    18. Resolving-map branches after alias resolution [53, 54]¶

    Store Both = [x] -> {a: Q[x], b: R[x]} while R/1 is /1, then rebind R/1 to a /N artifact before the branch is demanded. Demanding it MUST report deduction-phase OutputMultiplicityMismatch(context = resolving-map-branch) before Host dispatch. The rebound /N branch stays invalid even when the Host double would emit exactly one Value; no first Value is chosen and no key is omitted.

    19. Unresolved external references [56, 57]¶

    In a Codebase where Ext/1 is stored by another unit:

    • W = [x] -> Ext[x] in a new unit MUST report OutputMultiplicityCannotBeInferred(reason = external-symbolic-reference). Inference MUST NOT consult the current Ext/1 alias.
    • W = [x] -1> Ext[x] is accepted without resolving Ext/1. If Ext/1 later resolves to a /N artifact, demanding the occurrence MUST report deduction-phase OutputMultiplicityMismatch(context = goal-declaration) before Host dispatch.
    • W = [x] -> [Ext[x], Z] infers /0 without resolving Ext/1.

    20. Hash-qualified Root target [58]¶

    1. Store Main = [x] -1> $main(x) as Main/1 → hash-m1.
    2. Store a Voyage Plan whose Root is root Main#<prefix of hash-m1>/1. The prefix MUST expand to the full hash-m1 when the plan is stored, exactly as for a hash-qualified Goal reference.
    3. Rebind the Main/1 alias to a new artifact hash-m2.
    4. Lay the stored plan's default target, send 7, and demand the Root occurrence.

    The Root occurrence MUST select hash-m1 without consulting the current Main/1 alias, and the declaration itself MUST NOT have created any occurrence or deduction before the send. Repeat with an unqualified root Main/1: the Root occurrence then selects hash-m2, the artifact visible at its demand. A prefix that matches no stored artifact MUST fail validation with HashNotFound, and one that matches several with AmbiguousHashPrefix.

    21. lay creates the voyage/Cable pair before returning [R15]¶

    Call lay(P/1) and instrument both planes. The operation MUST return its opaque CableHandle only after Vessel's voyage and Cable's data-plane lifecycle both exist. At return there is still no admitted segment, pin/lease, occurrence, deduction, Host work, or alias observation. Failure to create either half returns no usable handle and leaves no half-live public Cable.

    22. Segment activation reuses Cable declaration leases [R14]¶

    Admit one input with pinned Scheduler registry, Host capability, and forwarding allowlist identities. When the segment becomes active, Cable supplies its input tuple and immutable lease references to Vessel. Vessel MUST create the Root occurrence from those leases and perform no second pin or registry negotiation. Replacing a registry after admission affects no active or queued segment whose lease was already accepted.

    23. Scheduler and Host projections cross Cable correctly [R13]¶

    Attach Scheduler-addressed scope policy and Host-addressed leaf policy in one segment. BeforeAttempt, Hold, ChildScopeOutcome, and equivalent scope events MUST reach Scheduler only. After Scheduler authorizes a leaf, Host MUST receive hostPolicies[] only and MUST never receive directPolicies[] or the Cable handle. Storing Scheduler-determined outcomes in Cable MUST NOT let Cable choose or reinterpret them.

    24. Structural closure and drainage are both required [R9, R11]¶

    Run four variants:

    1. Cable has drained installed work but one reachable undeduced occurrence is ready and Scheduler withholds it.
    2. Vessel reports no reachable structural work but one installed Host emission or downstream channel operation remains active.
    3. A conditional branch is unselected, or /0/empty /N creates no downstream invocation.
    4. Both structural closure and Cable drainage are true.

    Variants 1 and 2 MUST emit no EndOfResult; silence is not completion. Variant 1 remains pending until Scheduler demands the occurrence or makes an accepted terminal decision. Variant 3 creates no reachable frontier for the absent path. Variant 4 linearizes exactly one segment terminal. After decommision, EndOfStream additionally waits for Vessel to close topology publication and for Cable to propagate every segment terminal and drain every channel/attempt.

    25. Final composition cannot bypass a plane [R17]¶

    Complete the same multi-segment Cable with a same-process and split-process Runtime. Vessel supplies immutable deduction/position provenance; Cable supplies completed segment order and drainage evidence. The stateless Runtime composition layer MUST produce identical Fully Touchdown Cable membership, order, and ordered SegmentOutcome values in both profiles.

    An outward adapter that reads Vessel or Cable private storage directly instead of the two immutable result ports is non-conforming, even if its example output happens to match.
