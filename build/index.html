    __C — Subsea Cable¶

    Programs are not instruction sequences. They are executable intent.

    Subsea Cable is a small structural language for describing what Goals exist, how they depend on one another, and where concrete computation begins. It does not replace Go, Java, Rust, Python, WASM, or another Host language. It gives their functions and services a common dependency structure.

    A Subsea source file is a Voyage Plan. It is written as .vyg, and it becomes useful through a live Subsea Cable Runtime that cooperates with a Scheduler and a Host.

    Status: evolving pre-1.0 language specification. There is no official Runtime. Implementations must pin the exact specification revision and profile they support. See Runtime availability for dated implementation evidence and remaining adoption gates.

    This README is an orientation, not an independent semantic authority. On any difference, follow the applicable area-scoped source in GOVERNANCE.md—especially the Language Reference, grammars, and conformance corpus. If those sources disagree with one another or with the decision log, report the conflict rather than silently choosing a winner.

    Why Subsea Cable exists¶

    Traditional code often asks functions to do three different jobs at once:

    describe the program     implement computation     decide execution
        Goals                  Functions                Scheduler

    Subsea Cable separates them.

    • A Voyage Plan declares Goals and dependency structure.
    • A Host gives grounded leaves concrete meaning.
    • A Scheduler decides eligibility, attempts, and outcomes.
    • A Runtime lazily realizes and operates the resulting Cable.

    The separation keeps orchestration visible without forcing one programming language, scheduler, deployment model, or effect system on every implementation.

    The important leap: the program can keep its future open¶

    Most DAG systems require the whole executable graph before work begins. Most general-purpose languages discover later work by hiding it inside function calls. Subsea Cable takes a different position:

    The dependency structure is explicit, but it does not have to be fully realized yet.

    A Voyage Plan may contain symbolic Goal references. The Runtime resolves one reference only when that exact occurrence is demanded. A Host-produced Value may then select a conditional branch, supply the arguments for another Goal, or reveal that no downstream occurrence is needed at all.

    The result is not a static graph and not a call stack. It is a live Goal DAG disclosed one committed structural step at a time.

    That distinction enables several properties at once:

    • Values may shape later structure without hiding dependencies in functions. A branch is visible as structure, but the unselected side never becomes part of the realized Cable.
    • The Runtime may begin useful work before the whole graph is known. It keeps only a bounded Touchdown window ahead of actual demand.
    • An Agent may revise the still-undeduced future of a live voyage. It stores a new immutable Goal artifact and rebinds a symbolic Name/Arity.
    • The past cannot be rewritten. A committed deduction records the exact artifact hash and structure it selected; installed topology never mutates.
    • The finished voyage remains explainable. Provenance records how authored intent became the grounded leaves that actually ran.

    This is the central Subsea Cable trade: keep the structure open long enough to respond to reality, while making every realized decision immutable enough to inspect, reproduce, and compare.

    Not just another DAG DSL¶

    Model Where later structure lives What happens to history
    Function-oriented program Hidden inside calls and control flow Usually reconstructed from traces
    Static workflow DAG Entire graph fixed before execution Graph is inspectable, but its future is closed
    Subsea Cable Explicit symbolic structure, deduced when demanded Every selected artifact and reduction is committed

    Subsea also refuses to solve this by becoming a universal workflow engine. It defines the portable structure and the cooperation boundaries; existing Hosts and Schedulers retain their own strengths.

    For the longer argument—why an agent needs to answer "how did I get here?" and how Subsea Cable compares with agent loops, Airflow, Temporal, and Nix—read Why Subsea Cable.

    The whole model at a glance¶

    Authored .vyg Voyage Plan
          |
          v
Vessel control plane ---- asks Carousel for one demanded deduction
          |                                      |
          | TopologyInstall                      | one atomic structural step
          v                                      |
Cable data plane <-------------------------------+
          |
          +---- Scheduler decides what is eligible and what outcome counts
          |
          +---- Host evaluates grounded function leaves and $Anchors
          |
          +---- routed Values may reveal the next structural demand
          |
          v
EndOfResult per input, then EndOfStream after decommission and drainage

    These names are deliberately distinct:

    Name Meaning
    Goal A named structural intention with an input arity and output multiplicity.
    Voyage Plan The authored .vyg source. It is a blueprint, not a running Cable.
    Subsea Cable Runtime The complete deployment-neutral whole.
    Vessel The control plane that owns the voyage and its still-open structural future.
    Carousel Vessel's mechanism for one requested atomic deduction.
    Cable The data plane that operates installed topology, channels, Values, and terminals.
    Scheduler The authority for eligibility, attempts, and outcomes.
    Host The provider of primitive semantics, function-leaf evaluation, and $Anchor implementations.
    Touchdown A demanded structural path has reached a concrete Host-provided leaf.

    The components may live in one process, several libraries, generated code, or remote services. The model fixes logical ownership, not packaging.

    Watch one voyage unfold¶

    Consider a service-recovery plan whose next action depends on a diagnosis:

    root RecoverService/1

RecoverService = [incident] -1> [
    Diagnose[incident],
    [diagnosis] -> [
        diagnosis["kind"],
        {
            transient: Retry[diagnosis],
            regression: RollBack[diagnosis],
            _: Escalate[diagnosis],
        },
    ],
    Verify,
]

Diagnose = [incident] -1> $diagnose(incident)
Retry = [diagnosis] -1> $retry(diagnosis)
RollBack = [diagnosis] -1> $rollback(diagnosis)
Escalate = [diagnosis] -1> $escalate(diagnosis)
Verify = [action] -1> $verify(action)

    The plan keeps the diagnosis and each possible action visible. Only the selected branch becomes work; an unselected branch observes no Goal alias and produces no leaf. An authorized Agent may publish a safer RollBack/1 definition before that occurrence is demanded. Already committed decisions keep their original definitions.

    The caller observes Values and the outcome of each input segment. After decommission and drainage, a Runtime supporting voyage results joins the reached leaves to their recorded ancestry. This is an authoring example, not a claim that a downloadable recovery integration is available today; check Runtime availability.

    The plan can revise its open future while preserving evidence of its past.

    A small Voyage Plan¶

    root PublishReport/1

PublishReport = [request] -> [
    Fetch[request],
    Transform,
    Publish,
]

Fetch = [request] -1> $fetch(request)
Transform = (source) -> $normalize(source)
Publish = [report] -0> $publish(report)

    Read it from the outside in:

    1. root PublishReport/1 names the default target and its input arity. It does not contain an input or start evaluation.
    2. PublishReport is a serial Goal: fetch, transform, then publish.
    3. Bare downstream Transform and Publish receive the preceding Value through the language's narrow unary-routing shorthand.
    4. Fetch and Publish reduce to Host Anchors. The Host resolves $fetch and $publish.
    5. Transform is a function leaf. Its body belongs to the Host rather than to Subsea's structural deduction engine.
    6. -1> and -0> declare one output and no output. Fetch must declare -1> because an Anchor's output is opaque to inference, while PublishReport can use plain -> because its structure determines the result.

    The plan says nothing about threads, machines, retries, containers, or where the functions are implemented.

    The structural vocabulary¶

    Subsea has a deliberately small set of structural ideas. Learn their shapes first; their exact validation and identity rules live in the language reference.

    Serial dependency¶

    Pipeline = [input] -> [A[input], B, C]

    Square brackets say that later stages structurally depend on earlier stages. They are not a function-call stack. Values are routed only by explicit arguments or the narrow bare-downstream shorthand shown above.

    Parallel independence¶

    NotifyAll = [message] -> {Email[message], Chat[message]}

    Curly braces say that siblings have no dependency edge between them. They permit concurrent execution but do not require it. An unkeyed parallel group publishes no outward Value; a keyed resolving map is used when named branch results must be combined.

    Conditional structure and guarded recursion¶

    CountDown = [n] -1> [
    n == 0,
    {
        true: Done[],
        false: CountDown[n - 1],
    },
]

    The selector exposes exactly one structural branch. An unselected branch creates no occurrence and resolves no alias. Each selected recursive step creates a new child occurrence, so the realized Cable remains a DAG even though the definition graph is recursive.

    Concrete leaves¶

    Add = (a, b) -> a + b
Send = [message] -0> $send(message)

    Every demanded path eventually reaches one of two Host-provided leaves:

    • a named function-arrow leaf such as Add;
    • an opaque Host Anchor such as $send.

    Subsea itself has no hidden native effect. Anything that touches the world is behind a Host boundary.

    How metadata¶

    @parallel(3) Process
@timeout("30s") NotifyAll[message]

    An @policy attaches ordered How metadata to exactly one structural occurrence. It does not change the Goal topology. Scheduler-addressed policies affect eligibility, attempts, or outcomes; Host-addressed policies affect only one grounded leaf invocation. Concrete policy meanings belong to declared Runtime profiles, not to names guessed from the annotation.

    From a plan to a live Cable¶

    Subsea does not treat a Goal as a synchronous function call. The outward lifecycle is intentionally separated:

    cable = lay(Target/arity)
send(cable, input)
observe zero or more Values, then EndOfResult
send(cable, nextInput)
...
decommision(cable)
observe EndOfStream and the final CableResult

    The spelling above describes the Runtime API contract; it is not .vyg syntax.

    Inside the laid Cable, each installed Goal connection is a logical asynchronous channel. FIFO delivery, capacity, rendezvous at capacity zero, and backpressure belong to the Cable data plane; the source language does not expose a chan type. The same connection can carry a one-Value result or a multi-Value stream, and explicit terminal frames—not silence—say when that result has ended.

    Each admitted input opens one serial result segment. The active segment drains before the next input begins disclosure, deduction, alias observation, prefetch, or Host dispatch. On success, a segment emits:

    • /0: no Values, then exactly one EndOfResult;
    • /1: exactly one Value, then exactly one EndOfResult;
    • /N: zero or more Values, then exactly one EndOfResult.

    A failed or cancelled segment still ends with exactly one EndOfResult, which carries its failure and terminates only that input segment.

    Silence is not completion. EndOfResult closes one input segment. EndOfStream is different: it appears only after decommision, structural publication has closed, every segment has ended, and the Cable has fully drained.

    The final CableResult combines the Fully Touchdown Cable—the ordered hashes of the grounded leaves actually reached—with one ordered segment outcome per admitted input.

    Lazy deduction makes the structure live¶

    A Voyage Plan is not expanded into a complete graph before execution.

    When an occurrence is demanded, Vessel asks Carousel to resolve that exact symbolic Goal reference and commit one reduction. Vessel then publishes the complete new topology slice to Cable atomically. Cable never resolves aliases or deduces structure; Vessel never carries channel frames or owns live Values.

    This boundary allows later Values to affect which structure is demanded next. It also allows an Agent or operator to author a new immutable Goal artifact and rebind Name/Arity while a voyage is live:

    • committed deductions and installed topology never change;
    • an undeduced occurrence observes the alias only when it is demanded;
    • Vessel never invents a replan autonomously from an outcome.

    That live feedback loop is why a general-purpose Subsea Runtime is more than a compiler that emits Host code and disappears.

    What this architecture buys you — especially if you are an Agent¶

    The pieces above reinforce one another. Removing any one of them produces a more familiar system, but loses part of the point.

    A planning language an Agent can safely author¶

    An Agent can propose Goal structure instead of generating an opaque script or smuggling orchestration into one large tool call. The plan is inspectable before it runs, each effect boundary is named, and a live correction changes only occurrences that have not committed yet.

    A .vyg Voyage Plan is validated before any leaf runs. Each committed deduction records its occurrence, applicable identity, resulting structure, and active lineages, plus the observed Codebase revision when alias resolution occurs. A named Goal deduction records the exact selected artifact hash; an inline Goal-arrow stage instead records referenceKind = inline-arrow, because its enclosing artifact supplies its identity.

    This makes replanning a precise operation rather than permission to rewrite the execution history. An authorized Agent stores a new immutable Goal artifact and atomically rebinds Name/Arity; committed deductions keep their selections, while only later-demanded undeduced occurrences can observe the new hash.

    Host-native computation without Host-owned orchestration¶

    Subsea does not ask the language to reimplement databases, network clients, WASM continuations, Go channels, or application libraries. Those remain Host capabilities. What Subsea owns is the Goal structure that says when and why a leaf is reached, which Values connect it to other leaves, and which policies are addressed to the Host or Scheduler.

    When an LLM serves as a $Anchor leaf, its grounded envelope can stay focused on that occurrence's arguments and lineages instead of an ever-growing transcript. The syntax also rejects hidden Goal or Anchor occurrences inside value expressions outside a function-arrow leaf. It cannot inspect an opaque Anchor implementation, so keeping existing orchestration out of one large Anchor remains an authoring and review discipline. Scheduler-addressed policies govern eligibility, attempts, or scope outcomes; Host-addressed policies affect only one grounded leaf invocation.

    Concurrency without baking in one scheduler¶

    Serial and parallel structure state dependency and independence. They do not hard-code a thread pool, cluster, retry loop, quorum rule, or failure policy. The same Voyage Plan can therefore retain its structural identity while a different Scheduler profile makes different execution choices.

    An auditable bridge from intent to effects¶

    The authored plan, demand-time alias selection, committed reductions, installed topology, grounded leaf hashes, and segment outcomes remain distinguishable. The Runtime can answer both “what did the author mean?” and “what concrete work did this voyage actually reach?” without pretending those are the same object.

    Structural reuse without pretending effects are pure¶

    A later voyage may reuse prior immutable structural segments when the relevant identity inputs match. It commits new occurrence records that refer back with reusedFrom; it never edits an earlier ledger. Structural reuse does not silently reuse a Host outcome or replay an effect. That stronger behavior needs its own explicit contract.

    An Agent authors a live voyage through Vessel's control surface. Vessel owns the voyage state and open structural frontier; the Agent or operator remains the author of every replan.

    What Subsea deliberately does not decide¶

    Subsea defines structural intent and portable boundaries. It does not ship or designate an official:

    • Scheduler;
    • Host or Anchor registry;
    • Runtime implementation;
    • process or network topology;
    • retry, timeout, batching, or resource policy vocabulary;
    • programming language for leaf implementations.

    Implementations may make reversible profile choices. A change to source syntax, structural semantics, identity, diagnostics, component ownership, or portable policy contracts requires the repository's proposal and activation process.

    Prepare your first workflow¶

    Pick one bounded task and write its dependencies as a Voyage Plan. Name the inputs and outputs of each leaf and keep existing tool implementations behind Host boundaries. You can review that plan before a Runtime integration is ready.

    Using the language and maintaining its execution guarantees are different commitments. The adoption guide helps you choose a supported implementation, check its revision and capabilities, and keep your own work focused on Goals and Host integration. Runtime availability records the implementation evidence and the next runnable scenario.

    Repository and naming scope¶

    This repository contains the language specification, grammar, conformance corpus, philosophy, governance, and implementation-neutral contracts. Production Host, Vessel, Cable, Carousel, Scheduler, adapter, and complete Runtime code belong in independent repositories.

    The official language name is Subsea Cable. __C is its visual short mark, .vyg is its source extension, and subsea-cable is the portable slug and language identifier. The language is not called “SubC,” and __C is not a code identifier.
